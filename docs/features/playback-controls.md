# Playback controls and queue

The playback screen is available from the mini-player and video details. It contains native video controls, 0.5–2× speed, previous/play/next, repeat off/one/all, autoplay, sleep presets (15/30/60 minutes) with explicit cancellation, and queue selection/removal/moving. Preferences persist locally; the transient queue and timer do not survive process termination. Autoplay off stops at every video end, including when repeat is selected. With autoplay enabled and repeat off, the final queue item stops rather than restarting.

Removing a noncurrent item keeps the current source; moving items preserves the active identity. Removing the active item selects its next neighbor, or the previous item if it was last. Removing the only item clears playback. Selecting the currently playing downloaded item retains its local source; repeat also preserves local/selected-part playback. Source transitions are serialized and stale requests cannot autoplay. Load failures have a visible retry action. Sleep expiry invalidates pending loads, and foregrounding rechecks the absolute deadline. Background timer execution still depends on OS JavaScript scheduling and needs device acceptance.

Verification: `bun run test`, `bun run typecheck`, `bun run lint`, `git diff --check`. Tests cover preference recovery, queue identity/end policies, native replacement ordering/failure recovery, timer cancellation and timer expiry while API/native work is pending.

Device acceptance remaining: launch a development build (existing MMKV native dependency), play a playlist, reorder/remove/select items while loading, confirm the final-item behavior for every repeat/autoplay combination, change playback speed and relaunch, set/cancel a sleep timer and check foreground/background behavior, disconnect the network then retry, and play a downloaded item without networking. The video detail surface unmounts on blur so two mounted views do not compete for the native player. Screenshots and native media validation are unavailable in the CLI environment.

This independent feature branch touches the same player and video-detail surfaces as watch history and link sharing. Merge reconciliation must preserve history capture/resume and link parameters while retaining serialized transitions and queue ownership. English/Simplified Chinese catalogs also overlap other feature PRs.
