# Video application feature plan

Internal implementation and integration plan, 2026-10-18. The current batch contains six product features and four reliability fixes, each delegated to a subagent in an independent worktree and `feat/*` branch. This document is a separate planning-only PR.

**All ten implementation PRs (#3–#12) are open for review and none are merged. A PR ready for review is not merged or delivered.** The baseline checkout remains unchanged. These additions cover a useful first milestone; they do not establish full parity with general-purpose video applications, and the next backlog below is not implemented by this batch.

## Confirmed baseline

LiberBili is an Expo React Native application with English and Simplified Chinese UI and a reusable TypeScript Bilibili API package. Before this batch it has home recommendations, basic video search, video details with native progressive playback and part selection, a mini-player/basic queue, comments, local playlists, and first-part downloads with local playback. Its API already exposes broader metadata, creator, subtitle, premium, DASH/audio, live, and danmaku capabilities; API availability does not mean the app exposes or has validated those workflows. See `packages/api/PARITY.md` for the existing extractor inventory.

Material gaps include persistent viewing progress, user-facing search filters/history, creator discovery, a consistent icon system, playback preferences/queue editing, and validated link entry/sharing. Review also confirmed stale asynchronous resource/comment state, unsafe download lifecycle transitions, concurrent session bootstrap work, and fragile playlist storage loading. The current batch addresses those bounded areas before the larger playback/account/live features.

## Integration order and conflict ownership

The following is a proposed review/merge order once reviewers approve; it is not an instruction to merge automatically.

1. Session and playlist reliability: establish shared API bootstrap and persisted playlist behavior before broader workflows depend on them.
2. Resource/comment reliability and search: establish route/request scoping and submitted-query pagination.
3. Watch history, then playback controls: combine per-part history/resume with serialized source replacement, queue identity, repeat/autoplay, and sleep ownership. Do not drop history save points when adopting the new playback controller.
4. Link sharing: reconcile route BV/part/time identity and explicit seeks with saved resume positions. An explicit requested part/time takes priority over saved history; remove stale link parameters when queue navigation selects another video.
5. Creator discovery: preserve uploader navigation and related preview while retaining resource BV guards, scoped comments, share actions, and focused playback routing.
6. Download lifecycle: retain playback/history compatibility for local files while applying ownership checks to all native task callbacks and filesystem cleanup.
7. Icons last among overlapping UI edits: apply wrappers and accessible labels to the final controls, then reconcile both locale catalogs. Its dependency-only portions can be reviewed earlier.
8. Merge the planning document with the final reviewed PR links/statuses. Re-run integration checks below on the resulting branch before release.

## Post-integration acceptance

Run these against the integrated branch, not just the independent feature heads:

- `bun install --frozen-lockfile`, `bun run test`, `bun run typecheck`, `bun run lint`, and `git diff --check`.
- `bun run i18n:extract`; review the catalog diff and fill all new English/Chinese messages, then re-run affected checks.
- In `packages/app`, `bunx expo-doctor` and production Expo exports for supported targets. A successful bundle is not native-device acceptance.
- Use a development build with the existing MMKV/native dependencies on iOS and Android. Capture screenshots/recordings for review in light/dark themes, narrow and wide layouts, and large text.
- Check VoiceOver/TalkBack labels, keyboard submit, horizontal filters/history scrolling, loading/error/empty/retry states, and persisted settings after restart.
- Exercise rapid video and creator transitions, delayed/out-of-order requests, queue advancement, back navigation, explicit part/time links versus resume history, and background/foreground progress saving. Verify old routes cannot restart playback or display another video's comments.
- Test share sheet/cancel, BV/AV and short links, invalid/premium/live link rejection in the VOD entry flow, and cold/warm custom-scheme opens. Universal links and inbound share extensions remain out of scope.
- Test downloads across pause/resume/remove/retry, app restart, missing files and offline playback, including delayed callbacks after removal. OS background scheduling and transfer restoration require real native validation.
- Check corrupted persisted values and concurrent API bootstrap failures. Keep account cookies, tokens, downloaded media and Expo output out of commits.

This batch's PRs disclose missing physical-device/native visual QA. Public requests may be blocked by Bilibili anti-bot controls, while restricted or premium media can require account/region entitlement. Local unit tests need no account; they do not validate authenticated, premium or live playback. Review and native acceptance remain outstanding until explicitly completed.
